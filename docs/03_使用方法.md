# 使用方法

以下命令在当前中转机执行。原部署继续可用；这里以迁移包副本为例。导出前须运行 `bash scripts/install_relay_env.sh`，或使用原环境 `/home/ccic/piper_capture/.venv/bin/python`。

## 1. 检查并录制

```bash
cd /home/ccic/piper_migration_20260918/relay/program
/usr/bin/python3 receiver.py status
bash record.sh --task '将方块放入盒中'
```

输入 GOS SSH 密码，看到 RECORDING 后示教；Ctrl+C 结束，再标记本次任务是否成功，等待补传完成和 SAVED 输出。每次启动/结束对应一个 raw 目录。服务 idle 时主臂不发指令导致 action_stale 可以正常出现；正式采集期间应保持有效示教，确认从臂跟随。

定时录制 30 秒、结束后询问成功与否：

```bash
bash record.sh --task '将方块放入盒中' --duration 30
```

改变目标、数据位置、保留 GOS 副本的完整示例：

```bash
/usr/bin/python3 receiver.py --host 10.21.31.104 --user user \
  --root /home/ccic/piper_datasets/raw --keep-gos \
  record --task '将方块放入盒中'
```

默认校验接收后会释放 GOS 上对应 tar，raw 中保留完整副本。这个行为是采集传输设计；迁移程序包本身没有搬走或删除原程序。

## 2. 补传、查找数据

```bash
/usr/bin/python3 receiver.py sync
ls -td /home/ccic/piper_datasets/raw/*/
```

断网后可以重跑 sync，已有 .part 继续传，完整且校验正确的 tar 跳过。转换前应等录制结束且传输完成。

## 3. 检查与转换

把 EPISODE_ID 替换为 SAVED 输出的 raw 目录名，输入是整个 episode 目录，无须手动解压 tar：

```bash
.venv/bin/python export_lerobot.py --inspect /home/ccic/piper_datasets/raw/EPISODE_ID
.venv/bin/python review.py /home/ccic/piper_datasets/raw/EPISODE_ID \
  --output /home/ccic/piper_datasets/review.html
HF_HUB_OFFLINE=1 .venv/bin/python export_lerobot.py \
  /home/ccic/piper_datasets/raw/EPISODE_ID \
  --output /home/ccic/piper_datasets/lerobot/piper_task_001 \
  --repo-id local/piper_task_001
```

输出目录必须尚不存在，下一批可以命名 piper_task_002。多个 raw episode 可以作为多个位置参数传入同一命令，要求分辨率和 FPS 相同。默认筛选成功的完整录制，诊断/丢弃数据不导出；`--include-failed` 允许已正常结束但标记失败的录制，不会放行无效帧。默认只保留至少 15 帧的有效连续段。

原 raw 数据保留，转换不上传 Hugging Face。训练输入在 data/videos/meta；深度附件在 attachments/depth。一次示教经过质量分段可能成为多个 LeRobot episode。

## 4. 加载结果

使用 `.venv/bin/python` 执行以下 Python：

```python
from lerobot.datasets.lerobot_dataset import LeRobotDataset
ds = LeRobotDataset(repo_id='local/piper_task_001',
                    root='/home/ccic/piper_datasets/lerobot/piper_task_001',
                    video_backend='pyav')
print(len(ds), ds[0]['observation.state'], ds[0]['action'])
```

## 常见问题

| 现象 | 处理 |
| --- | --- |
| Unknown server / host key 错误 | 先 ssh 登录并核对目标指纹，确认 ~/.ssh/known_hosts 正确；不要跳过验证 |
| No CAN data for 5s | 确认供电和连接；会话重启后可能需要插拔 USB-CAN，服务会自动重连 |
| action_stale | 检查主臂有效示教状态及四类主臂指令，查看实际跟随；不要用从臂反馈填充 action |
| state_stale / joint_packet_skew | 检查 CAN 反馈、总线和接收延迟，先看原始时间与报文，不要直接放宽质量阈值 |
| 相机启动失败 | 检查连接、权限、库依赖和其他程序占用；查看 GOS collector.log |
| spool_limit_or_low_disk | 补传清理积压，检查两端空间，缩短单次录制；不要删除尚未校验接收的 tar |
| No valid continuous training segments | inspect 检查成功标记、诊断标记和有效连续帧数量 |
| Output already exists | 使用新的输出目录，避免覆盖已有数据集 |
| 视频加载出现 torchcodec/FFmpeg 错误 | 沿用已测 PyAV 后端和包内配套版本 |

原验收记录在 relay/program/acceptance_summary.md，仅代表采集链路和数据读写验收，不能代表正式任务训练数据质量。迁移包测试结果见 validation/。
