# 程序设计

## 数据流和模块

```text
主臂指令 + 从臂反馈 → 同一 CAN 总线 → USB-CAN → GOS collector.py
D435i RGB + Z16 深度 → librealsense RSUSB → realsense_c.py ↗
    → 按相机时间关联 CAN → PNG / JSONL / CAN 原始报文 → 原子 tar 分块
    → 中转机 receiver.py 经 SSH/SFTP 拉取、校验、ACK
    → raw/<episode_id> → export_lerobot.py → LeRobot v3 数据集
```

GOS `collector.py` 常驻：CAN 接收线程、相机线程、数据写入线程和本机 HTTP 控制端口。PNG 编码使用 4 个工作线程。`core.py` 负责协议解码、历史缓存、因果取样和时钟映射；`realsense_c.py` 通过 ctypes 调用现有 C SDK；`control.py` 从标准输入读取 JSON 并访问 `127.0.0.1:8765`。中转机通过 SSH 执行此入口，无须向网络开放 HTTP 端口。

中转机 `receiver.py` 负责录制控制与断点传输；`record.sh` 是录制快捷入口；`export_lerobot.py` 负责质量筛选、分段及官方格式写入；`review.py` 生成图像与状态/动作曲线 HTML。

## CAN 和字段

USB-CAN 为 candleLight / gs_usb，VID:PID `1d50:606f`，速率 1 Mbit/s。通过 PyUSB 访问，当前实现不需要 SocketCAN 的 can0。程序要求只发现一个兼容 USB-CAN，启用硬件 listen-only，不发送机械臂控制报文，不设置主从、使能或归零。

| 来源 | CAN ID | 输出 |
| --- | --- | --- |
| 主臂目标 | 0x155、0x156、0x157 | 六轴 action，rad |
| 主臂夹爪目标 | 0x159 | action 第七维，宽度 m |
| 从臂关节反馈 | 0x2A5、0x2A6、0x2A7 | 六轴 observation.state，rad |
| 从臂夹爪反馈 | 0x2A8 | state 第七维，宽度 m |

关节使用有符号大端 int32，毫度转 rad；夹爪宽度按微米转 m。角度模式的夹爪反馈不能当作宽度，会判无效。经典 CAN 没有发送方地址，必须保持主从报文 ID 唯一且配置正确。action 是总线上收到的主臂目标，不是主臂独立实测状态，也不是未来从臂反馈。

## 同步与质量

D435i 默认同时输出 RGB8 和 Z16，640×480、15 FPS。关闭 SDK global time，保存硬件时间戳、帧号、相机标定、深度尺度、原始 CAN 和主机接收时间。

相机在预热时用到达时间的低延迟样本估计与 GOS 单调时钟的偏移；录制期间固定映射。每个相机时刻关联此前最新 CAN 分量：分量年龄 ≤100 ms，六轴三包跨度 ≤20 ms，RGB/深度时间差 ≤35 ms。未来报文不用于填补当前帧；缺失动作不填零、不用 state 替代。重复帧、时间跳变或超阈值数据保留原因并判无效。

这是软件时间关联，存在 USB 传输、接收调度和漂移误差，不保证硬件同步精度。GOS 墙钟曾为 2024 年；目录日期可能与实际日期不同，关联用单调时钟。

## 存储和传输

一次 start/stop 是一个 raw episode，目录含 manifest.json 和多个 chunk_XXXXXX.tar。约每 2 秒或 30 个图像样本封块；tar 本身不压缩，里面 RGB/深度 PNG 无损压缩，CAN JSONL 使用 gzip。块内包含 `color/`、`depth/`、`samples.jsonl`、`can.jsonl.gz`。

数据块先写临时文件、fsync、原子重命名，再更新 manifest。中转机使用 `.part` 文件续传，验证大小及 SHA-256，fsync 后 ACK；默认 GOS 收到 ACK 后释放对应 tar。manifest 和 ACK 记录保留。`--keep-gos` 可禁止自动释放。

原始 CAN 事件队列上限 20000，待编码图像上限 120。队列溢出、相机超时、缓存超过 2 GiB 或剩余磁盘不足 512 MiB 会结束录制并标记失败。未完成录制在重启后标记 interrupted。已测网络约 2.6 MB/s，低于该配置无损采集约 6.6 MB/s，缓存会积压，持续时长受容量限制；尚未完成长时压力验证。

## LeRobot 导出

使用 LeRobot 0.4.4 官方 LeRobotDataset 写入 v3：`data/` 为 Parquet 状态和动作，`videos/` 为 RGB H.264，`meta/` 为元数据。`attachments/depth/` 保存原始 uint16 深度 PNG、内外参及来源映射；深度未对齐到 RGB，也不是标准视频训练特征。需要深度训练时另写读取逻辑。

默认仅导出 complete、成功、非诊断且未丢弃的录制。有效连续段按 15 Hz 网格选帧，间断处分割，不把缺口压缩成连续动作。默认每段至少 15 帧。一个 raw episode 可以生成多个训练 episode，tar 边界与训练 episode 边界无关。保留 `source.frame_index`、`source.monotonic_ns` 和 `sync.color_depth_ms` 便于溯源。

## 已知设备行为

USB-CAN 在 PyUSB 会话关闭后再次打开，已复现打开成功但收不到数据。因此服务长期运行，多次录制复用 CAN 会话；若重启后报 `No CAN data for 5s`，检查供电并重新插拔 USB-CAN，程序根据新 USB 设备编号自动恢复。打包和迁移文件本身不需要重启。
