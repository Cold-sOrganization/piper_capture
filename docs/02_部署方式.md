# 部署方式

## 当前两台机器

程序已经部署且原目录保留，可继续使用 `/home/ccic/piper_capture`。迁移包是独立副本；不要为了检查包而启动第二个 GOS 采集器。当前服务不是 systemd 开机自启，接收端在服务未启动时会尝试以 nohup 启动。

中转机可以直接执行包内接收程序，例如：

```bash
cd /home/ccic/piper_migration_20260918/relay/program
/usr/bin/python3 receiver.py status
```

该 status 命令在服务不存在时会启动服务。纯文件校验请只执行 SHA256SUMS 检查。

## 在新中转机部署

目标：Ubuntu 22.04、x86_64、Python 3.10。将整个迁移包复制到目标机任意目录。先安装系统基础依赖（本包不含这些 apt 包，需网络或对应 Ubuntu 离线仓库）：

```bash
sudo apt-get update
sudo apt-get install python3 python3-venv python3-paramiko openssh-client
```

包内 wheels 已包含导出所需 Python 二进制依赖。以下命令从包内目录执行，新建 `.venv`，不覆盖已有环境：

```bash
bash scripts/install_relay_env.sh
cd relay/program
HF_HUB_OFFLINE=1 .venv/bin/python -m unittest discover -s tests -v
```

安装脚本使用 `--no-index --no-deps` 安装已配套的 wheels，避免完整训练依赖解析和外网下载。这是经过数据读写测试的精简采集/导出环境，不是完整 LeRobot 训练环境；不要用一次 pip check 全通过作为本包成立的前提。换 Python 版本、CPU 架构或更老系统需重新准备匹配 wheels，不能直接复用。

接收端使用系统 `/usr/bin/python3` 和 apt 安装的 paramiko；导出/审阅使用新建的 `.venv/bin/python`。建立 GOS SSH 信任：

```bash
ssh user@10.21.31.104
# 核对机器指纹后接受主机密钥，成功登录后 exit 返回。
```

本包不携带密码、密钥或 known_hosts；运行时按提示输入密码，也可自行配置密钥后使用 `--key-auth`。

## GOS 已有 Piper 和 D435i 驱动

请优先按 [已有驱动环境部署](04_existing_drivers.md) 操作，只部署 piper_capture 并检查现有依赖路径。下面的全新 GOS 流程仅在相应依赖缺失时参考。

## 在新 GOS 部署

目标：Ubuntu 20.04、ARM64/aarch64、Python 3.8，Piper 主从已正确配置、D435i 和唯一的 USB-CAN 已接入。随包 RealSense 动态库是从原 GOS 复制的 ARM64 二进制，不能在 x86_64 使用。

在中转机包根目录执行，将 gos 子目录传到新 GOS（按实际情况替换 IP）：

```bash
scp -r gos user@10.21.31.104:/home/user/piper_migration_gos
```

以下命令只用于尚未部署的新 GOS。若目标目录已有程序或运行时，先比较版本并另行安排升级，不要覆盖运行中的部署：

```bash
sudo apt-get update
sudo apt-get install python3 python3-numpy python3-opencv python3-pil libusb-1.0-0 libstdc++6 libudev1
cd /home/user/piper_migration_gos
test ! -e /home/user/piper_capture && cp -a program /home/user/piper_capture
mkdir -p /home/user/agx_arm_ws
test ! -e /home/user/agx_arm_ws/vendor-python && cp -a runtime/vendor-python /home/user/agx_arm_ws/vendor-python
test ! -e /opt/realsense-rsusb-2.51.1 && sudo cp -a runtime/realsense-rsusb-2.51.1 /opt/realsense-rsusb-2.51.1
sudo cp -n runtime/udev/*.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
```

规则重载后在设备空闲时重新插拔 USB-CAN 和相机，让设备权限生效。规则是原机权限规则快照，应按新机用户管理要求审阅。检查依赖（这些命令不启动采集）：

```bash
PYTHONPATH=/home/user/agx_arm_ws/vendor-python /usr/bin/python3 -c 'import numpy, cv2, usb, gs_usb; print("Python dependencies OK")'
ldd /opt/realsense-rsusb-2.51.1/lib/librealsense2.so
```

ldd 不应出现 not found。正式启动只运行一个采集器：

```bash
cd /home/user/piper_capture
nohup bash start_gos.sh > collector.log 2>&1 </dev/null &
```

也可以返回中转机执行 receiver.py status 让接收端启动服务。不要并行运行其他占用同一 USB-CAN 或相机的程序。

## 固定路径与可配置参数

当前快照保留已验证代码，未改写部署路径：

| 项目 | 配置方式 |
| --- | --- |
| GOS SSH 地址/用户名 | receiver.py 全局参数 `--host` / `--user` |
| 中转机 raw 目录 | receiver.py 全局参数 `--root` |
| LeRobot 输出目录 | export_lerobot.py `--output` |
| GOS 程序和远程 spool 路径 | receiver.py 内固定 `/home/user/piper_capture` 及其 spool；更换路径需同时修改 call、ensure_service、sync |
| GOS vendor-python | start_gos.sh 内 `/home/user/agx_arm_ws/vendor-python` |
| RealSense 库 | 环境变量 `REALSENSE_LIBRARY`；默认 `/opt/realsense-rsusb-2.51.1/lib/librealsense2.so` |
| 采集缓存/频率/阈值 | collector.py `--help`；若改 spool 必须同步修改 receiver.py 远端路径 |
| 本机控制端口 | collector.py 默认 8765；control.py 也必须保持一致 |

因此建议新 GOS 沿用原用户和目录。新中转机非 ccic 用户须显式设置 `--root /home/实际用户/piper_datasets/raw`。全局选项放在 record/status/sync 子命令前。
